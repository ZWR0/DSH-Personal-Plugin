# 文脉护航

`@local/dsh-context-guard` · **0.1.1** · Web Host 插件

在每次模型步骤前调用当前会话预设自己的压缩服务。原生自动压缩失败时，护航插件先报错并停止本次模型请求，避免原有失败后继续请求的路径。它不自己生成摘要、不删历史、不挂载第二个压缩器，也不修改已有预设。

## 安装与生效

通过行囊宝匣或原生插件管理器安装本目录，重启原 Web Host 后刷新网页。安装后需重启原 Host 才能加载插件。它独立于暗金主题开关，不需要客户端脚本。

需要 Web 的 `agentPresets.serviceFor`、`tokenMeter` 与 `llm.resolveModelInfo`。通过公开的预设服务查询接口获得各会话隔离的 `compaction`；不能直接把 Web 已停用的全局压缩器开启。标准、PTC、minimal、cordis 预设自带原生压缩服务；自定义预设缺少服务时明确报错，不静默忽略。

## 阈值和预算

原生 `compaction-basic` 默认 `thresholdRatio: 0.8`。实际触发点还受模型窗口、输出预留及其 `headroomTokens` 约束，可能早于窗口的 80%。自定义触发比例、最近历史保留量、摘要模型和摘要输出预算仍由对应预设的 `compaction-basic.config` 管理；本插件不覆盖这些配置。若调整到 75%，在该预设中设置 `thresholdRatio: 0.75`，不要只改已停用的全局行。

护航的 `cordis.patch.yml` 还提供两项独立安全设置，可通过 profile 中 `local-context-guard` 行的完整 config 覆盖：

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `maxPressureRatio` | `0.9` | 压缩后允许继续请求的最大输入占比，须大于 0、小于 1；通常应高于原生触发比例 |
| `reserveTokens` | `8192` | 除模型声明的输出预留外，为后续动态上下文等保留的输入余量；非负整数 |

压缩后估算输入为宿主已有历史计量加上此次待入队消息。安全上限为 `floor(min(模型窗口 × maxPressureRatio, 模型窗口 − 输出预留 − reserveTokens))`。达到或超过上限、模型容量未知、当前预设缺少压缩器时停止请求并显示下一步建议。已声明的请求输出上限优先，否则使用模型默认值；两者均未声明时沿用宿主的零输出预留语义。

这不是每次 provider 请求的精确 token 保证：模型元数据可能配置错误，预步骤之后仍可能增加工具定义或动态上下文，单条超大消息、固定系统提示和图片成本也可能无法靠历史压缩解决。原生工具结果裁剪、模型切换检查和溢出恢复保持原有行为。本插件的额外计量不进入模型提示，也不产生一套持久缓存。

## 出错后继续

压缩失败时，查看会话中的原生压缩记录；可使用 `/compact` 重试，或调整该预设的摘要模型、摘要输出预算及历史保留配置。护航不会把失败或截断的摘要当成成功，也不会自动反复收费重试。原生压缩器可能已完成一部分裁剪或历史替换，失败不代表回滚；以会话记录为准。之后可继续同一会话，无需清空历史。

“达到输出 token 上限”是单次回答的输出预算，和输入上下文满是两个限制。压缩不能保证消除输出截断；长回答仍可能需要继续输出或调整模型请求的输出设置。

停用本插件只移除额外保护，原生自动压缩及其配置保留。已经进入处理的压缩请求由宿主维护，不因插件设置页关闭而取消。

## 验证

`node tools/context-guard-test.mjs` 验证失败阻断、取消、输入与输出预留、未知容量、原生决策透传、真实 Cordis 注册顺序和卸载。`node tools/check.mjs` 包含本测试。测试不消耗真实模型 API，不代表摘要模型一定能够生成有效摘要；真实模型效果须以运行中的压缩记录判断。
