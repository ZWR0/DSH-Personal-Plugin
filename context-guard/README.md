# 文脉护航

`@local/dsh-context-guard` · **0.1.4** · Web Host 插件

在每次模型步骤前，等待当前会话预设的原生预步骤监听器完成压缩，再检查实际请求预算。未降到提前压缩目标时，原生压缩器保留警告；只要压缩后的输入、最终待发送消息和输出预留仍满足护航安全上限，就继续请求。预算不足且待发送消息本身未超过上限时，通过同一压缩服务强制压缩一次历史，再重新计量；仍不足时停止请求。摘要与历史替换由原生压缩服务负责，已有预设配置保持不变。

## 安装与生效

通过行囊宝匣或原生插件管理器安装本目录。本版需要 Host 中的 `compaction/token-budget` 扩展接口；官方源码和本插件本身不会自动提供调用点。先按 [安装指南](../INSTALL.md) 应用 [压缩预算补丁](../patches/dsh-compaction-token-budget.patch)、构建并验证，再重启原 Web Host 和刷新网页。单独构建未打补丁的官方源码无法补齐接口。它独立于暗金主题开关，不需要客户端脚本。

需要 Web 的 `agentPresets.serviceFor`、`tokenMeter` 与 `llm.resolveModelInfo`。通过公开的预设服务查询接口获得各会话隔离的 `compaction`；不能直接把 Web 已停用的全局压缩器开启。标准、PTC、minimal、cordis 预设自带原生压缩服务；自定义预设缺少服务时明确报错，不静默忽略。

## 阈值和预算

原生 `compaction-basic` 默认 `thresholdRatio: 0.8`，还默认额外预留 65536 token。护航通过 `compaction/token-budget` 将额外余量限制为 `min(原生 headroomTokens, reserveTokens)`，默认最多 8192；原生配置更小的余量保留。同时将摘要输出上限限制为 `min(原生 maxTokens, summaryMaxTokens)`（默认最多 8192），避免延后压缩后，摘要请求仍预留过大的输出空间。每次检查仍由当前路由的最新模型容量与输出预算计算，模型窗口改变后无需写死触发 token 数。自定义触发比例、最近历史保留量、摘要模型和摘要输出预算仍由对应预设的 `compaction-basic.config` 管理；本插件限制额外输入余量和摘要输出上限，不改写预设配置文件。若调整到 75%，在该预设中设置 `thresholdRatio: 0.75`，不要只改已停用的全局行。

护航的 `cordis.patch.yml` 还提供三项安全设置，可通过 profile 中 `local-context-guard` 行的完整 config 覆盖：

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `maxPressureRatio` | `0.9` | 压缩后允许继续请求的最大输入占比，须大于 0、小于 1；通常应高于原生触发比例 |
| `summaryMaxTokens` | `8192` | 摘要请求的输出上限；正整数；原生配置更小的上限保留，不改变正常回答输出上限 |
| `reserveTokens` | `8192` | 除模型声明的输出预留外保留的输入余量，同时限制自动压缩的额外余量；非负整数 |

自动触发点为 `floor(min(模型窗口 × 原生 thresholdRatio, 模型窗口 − 输出预留 − min(原生 headroomTokens, reserveTokens)))`，而暗金仪表显示的是输入占整个窗口的比例。以窗口 131072、输出预留 32768 为例，旧额外余量 65536 会使触发点降至 32768（25%）；护航默认将触发点提高至 90112（68.75%）。窗口扩大到 262144、相同输出预留时，触发点为 209715（约 80%）。输出占比很大时必须早于 80%，不能靠隐藏压缩或减少输出预留绕过真实容量限制。

压缩后估算输入为宿主已有历史计量加上预步骤最终允许发送的消息（包含该阶段加入的动态上下文）。安全上限为 `floor(min(模型窗口 × maxPressureRatio, 模型窗口 − 输出预留 − reserveTokens))`。达到或超过上限、模型容量未知、当前预设缺少压缩器时停止请求并显示下一步建议。已声明的请求输出上限优先，否则使用模型默认值；两者均未声明时沿用宿主的零输出预留语义。

这不是每次 provider 请求的精确 token 保证：模型元数据可能配置错误，预步骤之后仍可能增加工具定义等输入，单条超大消息、固定系统提示和图片成本也可能无法靠历史压缩解决。原生工具结果裁剪、模型切换检查和溢出恢复保持原有行为。本插件的额外计量不进入模型提示，也不产生一套持久缓存。

## 自动补救与出错后继续

原生压力检查只计量已有历史，护航还计入本步最终待发送消息。因此，已有历史低于触发点时，加入新消息仍可能使请求越界。护航在阻断前通过 `compactIfNeeded(..., 'context-overflow', signal)` 强制压缩一次历史，使用原生摘要、持久化和取消机制；重新计量后满足上限即继续当前步骤。该补救最多一次，不输入要求会话空闲的 `/compact` 命令。待发送消息本身已达到上限或输出预留耗尽窗口时，直接停止。

压缩未达到提前目标时，查看原生警告和会话中的压缩记录。例如 32789 token 高于 32768 的提前目标，但不必然超过请求安全上限。补救后仍不足时，拆分过大的输入，或调整该预设的摘要模型、摘要输出预算及历史保留配置。未被原生监听器处理的异常直接传播，取消仍会停止处理。原生压缩器可能已完成一部分裁剪或历史替换，失败不代表回滚；以会话记录为准。之后可继续同一会话，无需清空历史。

“达到输出 token 上限”是单次回答的输出预算，和输入上下文满是两个限制。压缩不能保证消除输出截断；长回答仍可能需要继续输出或调整模型请求的输出设置。

停用本插件移除额外保护和余量限制，原生自动压缩恢复其配置的额外余量。已经进入处理的压缩请求由宿主维护，不因插件设置页关闭而取消。

## 验证

`node tools/context-guard-test.mjs` 验证额外余量限制、卸载恢复、模型容量变化与输出预留的触发预算，以及临界预算继续、91326/90112 越界自动补救、最终消息越界补救、补救失败与取消、超大待发送消息跳过无效压缩、安全上限阻断、未知容量、原生决策透传和真实 Cordis 卸载。`node tools/check.mjs` 包含本测试。测试不消耗真实模型 API，不代表摘要模型一定能够生成有效摘要；真实模型效果须以运行中的压缩记录判断。
