# 知忆书阁

`@local/dsh-context-library` · **0.6.2** · Host + Web 客户端

维护 Agent 身份、Owner 资料、项目、决策和长期记忆，在模型请求前按预算加载。日常通过界面编辑或导入 Markdown；不需要手动整理目录或编写元数据。Agent 通过书库工具提出修订；默认批准后保存，也可在设置中授予当前书库自动保存新增和更新的权限。

## 聊天复查与自动保存

「记忆建议」可设置首次复查轮数和后续间隔，默认第 5 轮开始、之后每 5 轮复查。按持久化 Session 的 `turn/start` 计数，同一轮的多个模型步骤不增加轮数，恢复聊天后继续计数。自动策略在对应轮次的模型上下文中提醒复查，不额外调用模型；无可靠新信息时不强行建议，模型是否提交仍需真实聊天验证。

「自动记忆」开关默认关闭，只能通过用户设置授权。开启后，有明确陈述或确认依据的新增、更新通过 `context_library_propose` 直接保存到当前加载的书库，并启用新增长期记忆，无需指定输出位置或手动导入。推断、删除和归档仍需点击批准。切换书库目录撤销授权；版本冲突不覆盖外部修改。关闭自动策略或插件后不提交修订。

新增的长期记忆提案默认在批准后启用；模型显式指定不加载时保持停用，既有条目启停状态不变。

未授权的建议显示在聊天输入区，可检查正文和依据后批准、拒绝或暂缓，沿用书库设置中的审批与历史记录。旧聊天纯文字中的“批准写入”不构成书库审批。更新 Host 后需重启 DSH 并刷新客户端。

## 0.4.4 更新

聊天框左侧书本入口与「掌上行舟」采用一致的透明工具按钮、主题文字配色和按压反馈。手机 / 触屏点击区为 44 × 44 px，图标为 16 px，桌面按钮为 28 px，按钮无边框与阴影，悬停时显示轻量底色；角标保留待审数量。首次显示按钮时即加载样式，无需先打开预览；保留键盘焦点与减少动态效果支持。

## 0.4.3 更新

聊天框小书入口改为轻量图标按钮，打开时高亮，待审修订使用角标。弹窗头部集中刷新与关闭图标，预算显示用量、比例和条目数；正文采用平整列表，点击条目展开摘要与来源，折叠区减少边框层级。刷新保留展开状态，支持键盘、点击遮罩和 Esc 关闭；减少动态效果偏好下停止旋转动画。

## 0.4.2 更新

条目管理改为单栏：分类、搜索、列表和编辑依次排列。属性与正文集成在同一个编辑区，属性默认折叠。移除编辑 / 内容预览切换，直接编辑正文；作用域筛选与新建按钮并排放入紧凑工具栏，不再使用筛选折叠卡片。启用加载和关键决策使用紧凑开关，历史恢复与审批保留。

添加资料只保留「导入文件夹」。选择包含 Markdown 的文件夹后预览分类，再确认导入；新建条目仍通过分类下的新建按钮操作。书库位置前置，模式和策略集中设置，预算默认折叠。

修订历史记录已保存版本；Agent 建议先进入待审修订，经批准后才写入书库。0.4.0 起自动策略同时启用主动建议，仅目录和关闭策略停用主动建议。

本次源码包含自动策略与 Agent 建议联动的 Host 调整。更新后停止原 DSH 进程，以原环境重新启动，再刷新网页；后续仅更新客户端时刷新即可。

## 快速开始

1. 安装本目录，重启 DSH，再刷新网页。
2. 打开「插件 → 知忆书阁」，先在顶部「书库位置」确认或选择目录，再导入资料或新建条目。网页不能调用原生目录选择器时，展开「当前绝对路径」填写 Host 路径并保存。
3. 保存或确认导入后，点击聊天框的书本按钮，检查下一次请求的加载计划。

通过「添加资料 → 导入文件夹」导入已有资料；也可在条目管理中选择身份、项目、决策或长期记忆，点击对应的新建按钮后填写并保存。

身份条目写 Agent 的定位与习惯；Owner 资料可作为长期记忆条目保存。新建条目自动生成 ID，属性中可调整作用域和状态，项目作用域需绑定目录。分类用于选择条目类型，作用域通过搜索框下方的紧凑下拉框筛选。

## 导入已有 Markdown

通过「添加资料 → 导入文件夹」选择目录 → 检查「导入预览」→ 点击「确认导入」。预览显示分类、新增或更新、启停状态；已有条目更新时保存历史版本。源文件不修改，导入后不会自动同步来源文件的变化。

### 自动分类

| 来源名称或路径 | 结果 | 默认状态 |
| --- | --- | --- |
| `identity.md`、`principles.md`、`personality.md` | 同一次选择中的文件按此顺序合并为唯一 Agent 身份 | 启用 |
| `user_profile.md`、`owner.md`、`owner-profile.md` | 独立 Owner 资料，ID 为 `owner-profile` | 启用 |
| 路径包含 `projects/` | 项目条目 | 停用 |
| 路径包含 `decisions/`，包括年份子目录 | 决策条目 | 停用 |
| 其余普通 Markdown、`memory/long_term/` | 长期记忆 | 启用 |
| `README.md`、`_template.md`、空正文 | 忽略 | — |

项目和决策需要在编辑区「条目属性」中改为项目作用域、绑定正确目录，然后启用。导入时先以停用的全局条目保存，不会自动推断项目的实际工作目录。若需要全局决策，应自行确认其全局作用域与启用状态。

选择文件夹时才有相对目录信息；单独选择一个项目文件时，浏览器通常只提供文件名，插件无法据此识别 `projects/`，会作为普通记忆处理。需要项目分类时选择对应文件夹，或导入后在编辑器中调整作用域和启停状态。保存后的条目类型不可直接修改；类型不合适时应在正确类别重新建立条目。

检测到 Axiom 目录布局时，会忽略不属于身份、Owner 或 Memory 的开发文档与运行提示词。仅导入一个普通文件时不会判断其是否为 runtime prompt；请检查预览，避免把 `prompts/system.md` 等实现协议当成长期记忆。

### 导入边界

- 每次 1–64 个 Markdown 文件，总正文最多 768 KB，单文件最多 128 KB；大目录分批选择。
- 原文件的 frontmatter 被移除，使用插件生成的 ID、分类和启停状态，不原样继承其元数据。
- 导入不是追加合并已有正文；标记为“更新”的条目会用本次转换后的正文替换，并保留历史。尤其是 Agent 身份，应一次选齐希望合并的身份文件。
- Owner 与身份使用固定 ID；其他导入 ID 由文件名和相对路径生成。改变选择方式或来源路径可能生成另一条目，请核对预览，避免重复。
- 确认时会重新校验预览版本和当前书库；期间发生变化需重新预览。
- 批量导入逐条保存，可能部分成功；失败条目会列出，不会自动回滚已成功的条目。
- 文件名重复、多套同名身份、明显凭据或目标格式错误会拒绝导入并显示原因。

## 导入资料与切换书库的区别

| 操作 | 文件位于哪里 | 会发生什么 |
| --- | --- | --- |
| 导入文件夹 | 浏览器所在设备选择的文件 | 读取选中的 Markdown，将内容发送给当前 DSH Host，写入当前书库 |
| 书库位置 → 选择文件夹 | DSH Host 所在设备的目录 | 切换书库位置，不转换、合并或搬移任何文件 |

原始 `Axiom/identity` 不是本插件书库格式，直接选作书库可能显示“缺少元数据块”。推荐使用导入入口，保留现有书库。换目录后旧书库及其历史、待审文件原样保留。

仓库提供 [通用模板](../examples/context-library/README.md)，不包含个人背景或真实记忆。推荐通过导入界面添加你自己的资料。

## 聊天框书本浮窗

小书按钮打开「记忆预加载」卡片，只显示下一次请求准备预加载的文档 Token 合计、分段占比条和各文档的 Token 数与百分比。色带与列表圆点使用相同颜色；长文档名可换行，完整路径可悬停查看。卡片不显示预算上限、加载历史、未加载列表或重复的审批区；审批仍可通过聊天输入区与设置中的待审修订完成。

合计按各文档加载块的 Token 数相加，包括自定义模式中替换身份的文档；不包含目录、整段上下文外层提示和其他运行时信息，因此不同于书库上下文总用量或整个模型请求用量。缺少原生 token-meter 时数值以 `≈` 标记粗略估算。卡片是下一次请求的计划，不能用作历史请求已发送的证据。空计划显示 0，不绘制占比色带。

记忆建议的首次轮数、间隔轮数与「自动记忆」开关在桌面排成一行，卡片随内容收窄；手机将标题单列，控件紧凑换行。刷新、点击遮罩、Escape 关闭和焦点恢复保留。

## 加载模式与预算

### 补充模式

保留原有系统段落，将选中的书库内容作为补充上下文。插件默认采用补充模式和自动策略。

### 自定义模式

在每个 agent 的作用域中，仅遮蔽 **`harness:identity`**，应用 Agent 身份条目，不在补充上下文中重复身份正文。以下内容保留：

- 部署人设前缀和后缀、其余系统约束；
- 真实工作目录、沙箱、审批状态等运行上下文；
- 工具定义与使用约束、技能机制、项目 `AGENTS.md` 指令；
- 历史会话与旧快照。

身份为空、停用、超出适用预算或同作用域存在同名身份段落时，替换可能不生效；查看状态与冲突原因。解决冲突后保存设置可触发重试。关闭自定义模式后恢复原身份。

Axiom 文档提供名称、原则和协作习惯，不会自动创建 Axiom runtime 的工具、检索器、任务控制器或历史连续性。身份和记忆均在现有指令层级、权限及当前明确请求内应用。

### 自动加载

| 类别 | 条件 |
| --- | --- |
| 身份 | 有效、生效且启用 |
| 项目 | 启用、项目作用域且当前工作目录位于绑定目录中 |
| 决策 | 启用、关键决策，全局或匹配当前项目 |
| 长期记忆及 Owner | `enabled=true`，全局或匹配当前项目 |
| 其他条目 | 按目录预算提供标题、摘要或读取入口，不自动加载正文 |

项目匹配使用实际目录与包含关系，同一项目的子目录可匹配。“不自动加载正文”不等于文件访问权限隔离；目录或可用读取工具仍可能提供条目信息。

策略可选自动、仅目录、关闭。仅目录不预加载正文，需要时通过 `context_library_read` 读取。自动策略同时启用 Agent 主动建议，按当前书库授权自动保存或逐条审批；仅目录和关闭策略均停用主动建议。关闭策略停止书库注入。停用整个插件会卸载其工具、provider、守卫和路由，保留文件。

界面不提供加载预算调节入口。条目列表显示启用状态和对应字符数，停用、归档或错误条目为 0；字符数按正文的 Unicode 字符计数，包含空白与 Markdown 标记，不含元数据。启用状态不代表每个会话都已实际加载，项目匹配与加载计划仍决定当次内容。加载保护保留在后端配置中。优先使用 DSH token-meter，否则采用字符数 ÷ 4 的粗略估算；完整条目放不下时列入省略清单，不截断正文。条目与计划有内容版本标记，文件变化在后续请求中生效，历史快照不改写。

## Agent 建议与用户审批

`context_library_propose` 使用当前书库位置，按用户设置自动保存符合条件的新增和更新，或提交待审修订。提示词引导模型根据明确的持久事实、偏好或已确认结论提出建议；推断须标记来源，一次性兴趣、假设和引用内容不应成为身份事实。按轮次复查随正常聊天工作，不额外调用模型，也不能保证捕捉所有变化。模型未调用工具却声称记忆已保存时，每轮最多追加一次已记录的修正，要求调用书库工具并如实报告结果；这会增加一次模型步骤，不构成授权。

在「待审修订」查看理由、证据、差异和加载影响，可同意、编辑后同意、拒绝或本次不记。批准校验文件内容哈希，外部修改产生冲突；需要重新对比后确认。批准只执行一次，提案 24 小时过期。取消、沉默或继续聊天均不算批准。

你在编辑器保存或确认导入是直接的用户写入，不必再次走 Agent 待审流程。待审正文不会进入正式加载计划。

工具守卫拦截受支持的直接文件写入与明显 shell 写入形式，但属于纵深防御；其他工具、混淆命令或动态执行可能绕过，不能当作强制文件隔离。实际权限由 DSH 运行环境控制。

## 存储与手动维护

默认书库：`<profile>/context-library`。设置保存在 `<profile>/context-library.json`；顶部「书库位置」显示实际绝对路径。

```text
context-library/
├─ identity.md
├─ projects/<id>.md
├─ decisions/<id>.md
├─ long_term/owner-profile.md
├─ long_term/<id>.md
└─ .context-library/
   ├─ pending/
   ├─ resolved/
   ├─ dismissed.json
   └─ history/<type>/<id>/
```

日常使用界面即可。需要自行放入书库的文件，必须采用 frontmatter + 正文，例如：

```markdown
---
id: owner-profile
title: 我的资料（Owner）
type: long_term
status: active
scope: global
enabled: true
---

默认中文回答；技术解释根据我的已有基础调整深度。
```

`id` 须匹配文件名，使用小写字母、数字、点、下划线或连字符；`type` 须匹配类别目录。项目作用域还需 `projectPath`，关键决策支持 `key`。手动文件未写 `enabled` 时，长期记忆默认不启用；这与界面快捷新建、导入时显式设置启用不同。

保存采用临时文件、fsync 与 rename。更新、删除及恢复保存历史快照，每条约保留最近 100 个版本。条目版本为内容哈希前 8 位；外部变更会触发版本冲突检查。路径检查拒绝链接条目和越界目标。备份时保留整份书库及 `.context-library`，源码目录不是自动备份。

## 更新与故障排查

Host 修改（包括 0.3.0 新增导入接口）需要停止原 DSH 进程、用原环境重新启动，然后刷新网页。仅改客户端时刷新即可。不要在旧实例仍运行时另起同端口实例。

| 现象 | 检查方式 |
| --- | --- |
| 导入按钮禁用 / 提示版本不同 | 核对页面的前后端 build，重启原服务后刷新；当前前后端兼容标记为 `0.4.0-compact-settings`，与包版本 `0.4.4` 用途不同 |
| 身份格式错误 | 使用导入功能转换原文，或检查书库 frontmatter；切换目录不会自动转换 |
| Owner 保存了但没有加载 | 检查条目启用状态、作用域、加载策略和预算 |
| 项目记忆未加载 | 导入后默认停用；设置项目作用域、绑定目录并启用 |
| 身份有效但尚未替换 | 检查自定义模式、预算、会话挂载及同名段落冲突 |
| 启动报 `EADDRINUSE :3080` | 停止已有实例后再启动，避免重复占用端口 |

## 验证与限制

从仓库根目录执行：

```powershell
node tools/context-library-core-test.mjs
node tools/context-library-import-test.mjs
node tools/context-library-integration-test.mjs
node tools/context-library-client-test.mjs
```

| 脚本 | 覆盖范围 |
| --- | --- |
| core | 存储、预算、项目匹配、版本、历史、审批、路径与凭据检查 |
| import | 身份合并、Owner 分离、嵌套决策、默认停用项目、预览、版本冲突、历史、文件限制 |
| integration | 真实 Cordis、Connection、SystemPrompt、ToolsService、Session；身份替换范围、owner 认证导入、过期预览、卸载 |
| client | Edge/Playwright 渲染；快捷编辑、文件导入、精简浮窗、悬停属性、折叠状态、版本提醒、Escape、窄屏 |

这些测试使用临时书库或模拟 Host 回复；不是完整真实模型回合。集成测试中的 Agent 为最小接口替身。测试依赖与浏览器统一通过[套件环境检查](../README.md#新设备安装前检查)解析，迁移设备时设置 `DSH_SOURCE`，必要时指定 `DSH_BROWSER_PATH`。Windows 符号链接测试在无建链权限时跳过。

仓库仅保留上表四个回归测试，不包含签发浏览器认证或改写运行中书库设置的本机诊断脚本。测试不能替代真实模型效果与 DSH 版本兼容性验证。

## 记忆差异审核（0.5.0）

待审卡片显示新增与删除行数，编辑提案时同时展示手动修改的实时差异。版本冲突时禁用批准，重新对比后再确认；原有逐条批准、编辑后批准、拒绝与暂缓保持可用。
