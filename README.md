# 暗金工坊 · DSH Web UI 本地插件套件

本仓库包含 **9 个 DSH 插件**，覆盖本地插件管理、会话清理、主题、引用、提问、上下文管理与保护、远程登录和移动工作台。安装时以所下载目录中的 `package.json` 为准。

版本核对日期：**2026-11-03**。插件统一使用四字中文名，名称不附加功能或英文后缀。包名、插件 ID 和配置路径保持兼容。当前版本见下表。仓库另附认证层兼容补丁与可选启动器；安装前须先核对其 DSH 基线和依赖。

插件使用 `@local/*` 包名，安装在 DSH profile 中。其余八个插件不直接修改官方包；远行之钥依赖匹配的 DSH 认证层扩展，仓库提供独立兼容补丁，不能只复制界面插件就获得固定 Token 能力。

## 获取源码

```powershell
git clone https://github.com/ZWR0/DSH-Personal-Plugin.git
cd DSH-Personal-Plugin
```

也可以在 GitHub 点击「Code → Download ZIP」后解压。首次安装选择克隆或解压后的插件文件夹，不要选择 ZIP 文件。更新已克隆的仓库前，先保存自己的修改，再按 Git 提示拉取更新；不要覆盖仍在使用的个人书库或凭据。

## 安装与更新

1. 首次使用时，在 DSH 原生插件页安装源码目录下的 `local-vault` 文件夹。
2. 重启 DSH 并刷新网页，进入「插件 → 行囊宝匣 → 目录安装」。
3. 选择源码根目录（克隆后通常为 `DSH-Personal-Plugin`），检查扫描结果，点击「一键安装选中项」。
4. 按安装结果提示完成重启或刷新。也可以通过原生插件页分别安装需要的插件目录。

通过本地目录链接安装时，profile 会引用源码，无需把源码再次复制到 profile。链接安装并不代表运行进程会自动重载所有修改：

| 修改内容 | 如何生效 |
| --- | --- |
| 客户端脚本、界面样式 | 刷新网页；仍旧时强制刷新 |
| Host 脚本、工具、提示词或 API | 在原终端停止 DSH，再启动，最后刷新网页 |
| 安装、依赖或插件配置 | 遵循原生管理器返回的重启提示 |

源码启动示例：在你的 DeepSeek Harness 源码目录下运行以下命令，并沿用原启动环境中的 `DSH_HOME` 等设置。

```powershell
node --import tsx/esm apps/cli/src/bin.ts web
```

**先在原终端按 Ctrl+C 停止旧实例，再启动。** `EADDRINUSE 127.0.0.1:3080` 表示已有进程监听该端口，不表示插件代码一定损坏；不要重复启动多个实例。切换 `DSH_HOME` 会切换数据目录，应保持原值。

## 知忆书阁：从这里开始

进入「插件 → 知忆书阁」，先在顶部确认书库位置，再通过「添加资料 → 导入文件夹」导入 Markdown。预览分类后确认导入，原始文件保持不变。Agent 身份描述它的定位与沟通习惯，Owner 与长期记忆保存你的资料和已确认偏好。

当前版本沿用 0.4.2 的单栏条目管理：选择分类、搜索或新建条目后，在同一个编辑区修改属性和正文，直接编辑正文，不再单列内容预览。作用域筛选与新建按钮集中在紧凑工具栏，属性按需展开，预算默认折叠；自动策略同时启用待审批的 Agent 建议。必要说明悬停或聚焦查看。

0.4.3 的聊天框书本图标带待审角标，浮窗集中提供刷新与关闭操作，展示状态、预算用量和条目名称；鼠标悬停查看更多说明，历史与其他条目按需展开。「待发送」表示下一次请求的计划，不能当成已发送给模型。

自定义模式**仅替换 `harness:identity`**，保留部署人设前后缀、其他系统约束、工具、运行环境、项目指令、技能和历史。身份文档不会自动赋予 Axiom runtime 的任务控制或检索能力。

详见 [知忆书阁使用说明](context-library/README.md)。公开仓库提供[通用书库模板](https://github.com/ZWR0/DSH-Personal-Plugin/tree/main/examples/context-library)；本地 `axiom-context/` 含个人资料，不属于发布内容。

## 其他插件

### 行囊宝匣

0.5.3 将“选择可卸载项 / 清空选择”合并为一个随选择状态切换的按钮。来源与插件详情可展开查看；按钮提供轻阴影、悬浮与按压反馈，支持键盘焦点及减少动态效果偏好。批量安装与卸载显示进度条、已处理数量及当前插件；进度按插件数量计算。已安装列表支持多选、二次确认卸载和逐项结果，失败项保留选择以便重试。批量卸载排除官方、不可移除项和行囊宝匣自身；离开页面后不再启动后续卸载，已经开始的操作会继续。

选择 **DSH Host 所在设备** 的插件总目录后自动保存并扫描。根目录及下两级中的合法 bundle 可被识别；不进入目录链接、隐藏目录和 `node_modules`。有效的已安装项跳过，同名来源冲突时显示原因。支持手动输入 Host 上的绝对路径；没有原生文件夹选择能力时也可点击「保存目录并扫描」。旧目录不可用时保留路径并提示重新设置。

移动插件目录后，输入新总目录并保存扫描，选中「待迁移」项后一键安装：仅对旧本地来源已不存在、包名一致且可移除的插件，自动移除旧安装记录并安装新来源，保留启停状态；有效来源和官方插件不迁移。失败后重新扫描重试，恢复所需启停状态保存在 profile 的 `local-vault-recovery.json`。不删除磁盘插件文件。行囊宝匣不迁移自身：若行囊宝匣已无法启动，请先在原生插件页移除旧行囊宝匣记录、安装新目录的 `local-vault` 并重启，再批量处理其他插件。配置保存在 profile 的 `local-vault.json`。

安装调用原生 PluginManager，逐项显示结果；失败不阻断其他项，也不自动批准安装脚本。离开页面后不再开始下一项，已开始的安装仍可能完成。

### 会话清道

在会话菜单中点击“删除会话”先预览并确认；插件页支持按项目、更新时间和名称筛选后批量清理。删除永久生效，没有撤回或回收站。运行中的会话禁止删除；已停止的当前会话可删除，随后刷新列表并切换会话。批量操作遇到失败会停止并保留剩余项。

当前实现适配 DSH 的 Agent 生命周期和 JSONL 会话目录，仅支持匹配 `DSH_HOME/sessions` 的存储布局。上游内部结构变化或路径校验失败时拒绝删除。验证脚本只操作临时会话。

### 暗金主题

在「插件 → 暗金主题」启停，跟随原生浅色 / 深色 / 系统设置。主题包含仪表条和回答导航，隐藏重复的原生用量读数；关闭后恢复原生样式。详细行为与兼容边界见 [主题 README](aurum-theme/README.md)。

### 引文速递

在同一条 assistant 正文中划选文本，点击输入框工具行的引用按钮。优先使用原生引用卡片，保留草稿；旧接口环境回退为 Markdown 引用。支持单字选区，超过 8000 个 Unicode 字符时要求缩小范围，不截断原文。思考区、编辑区及跨回复选择不处理。

### 选项领航

这是 Host 提示词插件，复用部署实际提供的 `ask_user_question` 和输入区问题卡片，不增加重复的工具或弹窗。引导模型先查证已有信息，只对关键缺失和必要取舍提问；必要答案到达前不执行依赖部分。它依赖模型遵循指引，无法保证所有需求歧义都被发现。

### 远行之钥

在「插件 → 远行之钥」管理固定 DSH 登录 Token，保存远程基础地址并通过手机扫码登录。固定 Token 由 DSH_HOME 的凭据库保存；轮换或撤销会使旧链接和认证 Cookie 失效，`DSH_WEB_TOKEN` 环境变量优先于界面设置。插件保存地址，不自动修改 Tailscale、代理或防火墙。

**0.3.2：**连接状态改为简洁信息栏，远程地址独占一行，移除重启要求和固定 Token 安全提示卡片。配置 Token 并保存地址后，可点击「显示登录二维码」，通过已有 `/link` 接口获取链接，在浏览器本地生成登录二维码供手机或平板扫码，不调用第三方二维码服务，也不依赖新增 `/qr` 接口（修复 HTTP 404）。隐藏二维码、修改地址、更新或撤销 Token、刷新状态或切到后台时会清除二维码。扫码设备仍需具备可达的网络路径；二维码包含登录凭据，请勿公开分享。

**安装前先阅读 [认证兼容补丁](patches/README.md)。** 已验证基线为 DSH `ce7073d51254c26cd63b22a60835b8f948deb447`；原版缺少相关 Connection 接口时，仅安装插件无法工作。Windows 可选 [Tailscale HTTPS 启动器](vpn-launcher/README.md) 通过参数指定源码目录，不包含本机凭据。

完整安装、固定 Token 设置及故障排查见 [远行之钥 README](remote-access/README.md)。

### 掌上行舟

支持星标关注与关注筛选，按状态组置顶重要会话；设置中可分别控制提问 / 审阅、授权、任务结束提醒及仅关注模式。待处理中心展示简短问题或授权原因，原生卡片完成决策。分类静音不会隐藏待处理项。关注与提醒规则保存到当前 profile 的 Host；音量等设备偏好保留本地，后台锁屏推送仍需宿主扩展。

声音反馈开关、状态、试听和音量调节统一在「插件 → 掌上行舟」设置；主工作台不显示声音控制区。开关与音量仅保存到此浏览器；刷新后通过页面操作激活音频。开启立即播放试听，暂停或失败时明确显示状态，静音停止已调度提示音。

会话卡片提供「工作区文件」入口，切换到对应会话后打开原生文件树，文件浏览、读取与渲染由宿主负责。当前版本不提供独立成果清单或变更对比。可在插件设置中开启「手机默认打开掌上行舟」；默认关闭，仅对触屏窄屏启动生效，保留深链接和主动导航。

0.2.0 在对话输入框下方添加「掌上行舟」入口，与知忆书阁统一触屏按钮设计；显示待处理 / 未查看角标。工作台增加状态筛选、授权 / 提问区分、最近动态与可选提示音，每个会话可直接打开宿主原生文件面板。移除使用介绍与重复说明。提示音依赖网页继续运行，尚不提供锁屏系统推送。

手机仍扫描「远行之钥」二维码登录同一个 DSH 网页，再点击输入框下方的掌上行舟图标，无需安装手机 App。后续可收藏远程基础地址，登录失效时重新扫码；电脑与 DSH 需保持运行，两端网络可达。

在「插件 → 掌上行舟」启停，启停会直接移除或恢复输入框入口与主面板。工作台按宿主真实状态分组会话：**等待我回答**（宿主报告待处理交互）、**正在运行**（宿主报告运行中）、**最近会话**（其余，且明确标注不代表已完成）；点击直接进入原生会话页，回复、提问卡片、附件与拍照上传都在那里完成。

每行提供「打开」与运行中的「停止」，以及「新建会话」和「刷新」。停止的状态为「请求停止中 → 已请求停止，等待确认 → 已停止」，最后一步以刷新后的宿主结果为准，过程中按钮禁用以免重复发送。连接胶囊区分已连接、正在重连、连接不可用，并显示最近同步时间；断线时保留内容并提示可能过期，恢复、窗口重新可见或手动刷新时才重新同步，**不轮询**。

布局默认自动：窄屏单栏，可用宽度 ≥ 820 px 且高度 ≥ 500 px 时列表 + 详情分栏；设置中可强制手机或平板布局。工作台样式使用 `mdk-` 类名和主题令牌；另对宿主插件标签栏的公开标记提供窄屏横向滚动适配。远程地址与登录仍由远行之钥负责，本插件不保存任何凭据。

本版本以 `main`（keyed）、`plugins.tab` 两类插槽和 `ctx.sessions` / `ctx.uiSession` / `ctx.connection` 服务为基线；PWA、系统推送与系统分享在宿主提供对应公开接口前不展示入口。完整说明见 [掌上行舟 README](mobile-deck/README.md)。

可选的 [Web 嵌入登录诊断](patches/WEB-AUTH-DIAGNOSTICS.md) 默认关闭，仅提供脱敏 HTTP 事实；不是嵌入浏览器 Cookie 兼容修复，也不改变现有认证策略。

DSH-Personal-Plugin/

迁移时复制需要的插件目录，在新设备重新安装，并重新选择本机路径。插件源码、profile 配置、模型凭据、会话与书库是不同资产；复制源码不会自动迁移其余数据。书库需连同 `.context-library` 一起备份，保留历史和待审记录；不要把个人书库或凭据当作公共插件源码分发。

## 新设备安装前检查

下载完整插件套件后，在插件源码根目录运行：

```powershell
$env:DSH_SOURCE = "C:\path\to\deepseek-harness"
node tools/check.mjs --doctor
```

`DSH_SOURCE` 指向 DSH 源码目录，不是插件目录、DSH_HOME 或 profile。源码目录须先安装依赖并完成构建；检查失败时按输出修复。仅安装插件无需运行开发回归测试，但建议迁移源码部署时先做此检查。使用含中文或空格的路径无需改脚本。

检查包含 Node >=24.9、测试依赖、React UMD、浏览器、关键构建文件与固定 Token 源码、构建接口。`DSH_BROWSER_PATH` 可指定测试浏览器的可执行文件绝对路径；脚本不自动安装依赖或浏览器，不修改凭据、认证设置或现有会话。源码接口存在不代表正在运行的旧进程已加载更新。

行囊宝匣扫描时会在警告中列出已知插件缺少的 Host 方法；每次安装前再次校验，不兼容时返回 `local-vault/incompatible-host`，不会先卸载旧记录或开始安装。请更新匹配的宿主与兼容补丁，在原 profile 重启 DSH 后重新扫描。检查只覆盖列明的 Host 方法，不能保证任意上游版本的客户端插槽、存储布局或方法行为兼容；原生插件页直接安装不会经过行囊宝匣的检查。

全部插件回归只需一个命令：

```powershell
node tools/check.mjs
```

命令先检查环境，再按固定清单顺序运行隔离插件测试，不自动执行目录中的其他诊断脚本，逐项汇总，任一失败返回非零状态。源码认证测试单独使用 tsx，其他集成测试使用构建模块，避免混载两套作用域。默认不测试可选诊断补丁；需要时运行 `node tools/check.mjs --patches`。测试使用临时数据和隔离浏览器，不代替手机真机或远程网络验收。请勿同时运行两份回归，以免截图输出相互覆盖。
